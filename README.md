# Media Review Hub

Сервис ревью видео и изображений, упрощённый Frame.io. Пользователи загружают ролики, worker обрабатывает их в фоне, ревьюеры оставляют комментарии с таймкодом и рисуют поверх кадра, владелец собирает апрувы. Сделан уровень **Core** тестового задания. Что не сделано, перечислено в конце.

Устройство системы и принятые решения описаны в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

Нужен только Docker (Node на машине не нужен).

```bash
cp .env.example .env
docker compose up --build
```

Сборка с нуля занимает около 3 минут, после неё стек становится healthy примерно за 30 секунд.

| Что | Адрес |
|---|---|
| Приложение | http://localhost:3000 |
| Письма (Mailpit) | http://localhost:8025 |
| S3 (MinIO, presigned URL для браузера) | http://localhost:9000 |

Демо-данные создаёт контейнер `migrate`: workspace «Demo Studio», проект «Spring Campaign» и три пользователя с паролем `password123`.

| Пользователь | Роль |
|---|---|
| `owner@example.com` | owner |
| `editor@example.com` | editor (загружает, создаёт ревью) |
| `reviewer@example.com` | reviewer (комментирует, принимает решения) |

### Режим разработки

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

Исходники подключаются bind mount'ом. Web работает через `next dev`, worker через `tsx watch`, оба перезапускаются при правках. Postgres открыт на `localhost:5433`, Redis на `localhost:6379`. Production-конфигурация от dev-файла не зависит.

Локально без Docker: `nvm use` (Node 22), `npm ci`, затем `npm test`, `npm run typecheck`, `npm run lint`.

## Переменные окружения

Все переменные проверяются zod при старте ([src/server/env-schema.ts](src/server/env-schema.ts)). Если чего-то не хватает, процесс сразу завершается со списком недостающих переменных.

| Переменная | Кто читает | Назначение |
|---|---|---|
| `APP_URL` | web, worker | Публичный адрес приложения: ссылки в письмах, CORS MinIO, проверка Origin |
| `DATABASE_URL` | web, worker, migrate | Postgres |
| `REDIS_URL` | web, worker | Очереди BullMQ и pub/sub для realtime |
| `S3_ENDPOINT` | web, worker | MinIO внутри сети compose (`http://minio:9000`) |
| `S3_PUBLIC_ENDPOINT` | web | MinIO для браузера (`http://localhost:9000`): хост входит в подпись presigned URL |
| `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | web, worker, minio | Доступ к бакету |
| `SMTP_HOST`, `SMTP_PORT`, `MAIL_FROM` | worker | Отправка писем в Mailpit |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | postgres | Инициализация БД |
| `LOG_LEVEL` | все | Уровень JSON-логов (по умолчанию `info`) |

## Образы

Один multi-stage [Dockerfile](Dockerfile) с таргетами `web`, `worker`, `migrate` и `dev`. Размеры по `docker image ls` после `docker compose build --no-cache` (arm64):

| Образ | Размер | Содержимое |
|---|---|---|
| `media-review-hub-web` | **191 MB** | `node:22-alpine` + `.next/standalone` (лимит ТЗ 250 MB) |
| `media-review-hub-worker` | 275 MB | `node:22-alpine` + ffmpeg + один JS-файл (esbuild-бандл, без `node_modules`) |
| `media-review-hub-migrate` | 165 MB | `node:22-alpine` + бандл миграций и seed + SQL-файлы |

- Процессы в контейнерах работают от пользователя `node`.
- В runtime-образах нет dev-зависимостей и кеша npm. Слой зависимостей пересобирается только при изменении `package*.json` (`--mount=type=cache`).
- У каждого сервиса есть healthcheck. `web` проверяет Postgres, Redis и S3 через `/api/health`, `worker` пишет файл-heartbeat, пока Redis отвечает.

## Как проверить вручную пункты раздела 9 ТЗ

| Пункт | Статус | Как проверить |
|---|---|---|
| `up --build` на чистой машине; `down` и `up` без `--build` | ✅ | Данные (пользователи, файлы в MinIO) на месте. `migrate` повторно не падает: применённые миграции записаны в `drizzle.__drizzle_migrations`, seed идемпотентен |
| `.env` без `S3_SECRET_KEY` | ✅ | Удалить строку из `.env`, выполнить `docker compose up web`. В логе `Invalid environment variables: - S3_SECRET_KEY: missing`, код выхода 1 |
| Остановить `redis` | ✅ | `docker compose stop redis`: `/api/health` отдаёт 503 с `"redis": {"ok": false}`, на страницах проекта и ассета баннер «Live updates are paused». `docker compose start redis`: всё восстанавливается без перезапуска web |
| `stop worker` посреди транскодинга, затем `start` | ✅ | Загрузить длинное видео и на прогрессе 10–50% выполнить `docker compose stop worker`. Worker дождётся текущей задачи (до 2 минут). При `docker compose kill worker` задача после `start` переобработается: идемпотентно, файлы и версия в одном экземпляре |
| 3 ГБ: закрыть вкладку на 40% и продолжить | ❌ | Возобновление после перезагрузки — уровень Advanced, не сделано. При попытке закрыть вкладку во время загрузки браузер предупреждает |
| Отключить сеть на 20 секунд во время загрузки | ✅ | Часть повторяется с backoff 1+2+4+8+16 с, поэтому обрыв до ~30 с переживается автоматически. Если дольше, файл получает статус «Failed», и кнопка Retry продолжает с незагруженных частей. Проверено остановкой MinIO посреди загрузки, SHA-256 совпадает |
| `.exe` под видом `.mp4`; обрезанный mp4 | ✅ | Версия получает статус «Processing failed: Not a video or image we can read.» после одной попытки, без повторов. Кнопка Retry доступна |
| 29.97 fps: последний кадр минуты | ✅ | Unit-тесты [timecode.test.ts](src/features/player/timecode.test.ts): кадр 1799 даёт `00:00:59;29`, 1800 даёт `00:01:00;02`. Таймкод комментария хранится как середина кадра в мс, и круг «кадр → мс → кадр» проверен для всех кадров первых 10 минут |
| Стрелка в маленьком окне → fullscreen | ✅ | Нарисовать стрелку («Draw on frame»), открыть комментарий и нажать `F`: кончик стрелки в той же точке кадра, в том числе при letterbox |
| Два ревьюера шага `any` одновременно | ✅ | Записывается ровно одно решение (блокировка строки запроса), второй получает 409, а в панели видит «Settled by … before you decided». Через API проверено 5 гонок подряд |
| Новая версия во время ревью | ✅ | Ревью получает статус «Outdated», ассет возвращается в «In review», кнопка «Restart review on vN» открывает мастер с теми же ревьюерами |
| Удалённый ревьюер открывает старую ссылку и дёргает presigned URL через API | ✅ | Страница ассета даёт 404, `GET /api/assets/:id/versions/:vid/playback` тоже 404. Членство проверяется в БД на каждом запросе, роль в сессии не кешируется |
| Публичная ссылка: 20 неверных паролей, отзыв | ❌ | Публичные ссылки (3.6) — уровень Advanced, не сделаны |
| `--scale worker=3` и 10 видео | ✅ | `docker compose up -d --scale worker=3` и загрузить 10 файлов: каждая версия обработана ровно один раз (`jobId = versionId`, блокировки BullMQ), нагрузка распределяется по worker'ам |

## Тесты

```bash
npm test        # 127 unit-тестов (Vitest)
```

Покрыто: правила согласования (`all`/`any`/`atLeast`, параллельные решения), таймкод (23.976, 25, 29.97, 59.94), нарезка файла на части и расчёт скорости, разбор вывода ffprobe и прогресса ffmpeg, геометрия аннотаций (letterbox, нормализация), markdown-lite и упоминания, reducer комментариев, курсор пагинации, параметры списка в URL, права ролей, env, хеширование паролей.

Каждую фазу я проверял в браузере сценариями на Playwright (одновременно несколько пользователей, отказы Redis/MinIO/worker, замеры производительности). Это были рабочие скрипты, в репозиторий они не вошли. Оформленные e2e-тесты и интеграционные тесты против compose — уровень Advanced, см. ниже.

## Не сделано

**Advanced:**
- возобновление загрузки после перезагрузки (IndexedDB), папки, drag & drop папок;
- HLS с двумя качествами и спрайт миниатюр для скраббинга (сейчас только MP4 720p и постер);
- сравнение версий, диапазоны в комментариях;
- несколько шагов согласования в UI (логика, хранилище и транзакция уже поддерживают; включается константой `MAX_STEPS`);
- публичные ссылки `/s/[token]`;
- CSP без `unsafe-inline`;
- профиль `e2e` в compose, GitHub Actions, reverse proxy для `--scale web=2`;
- интеграционные тесты, тесты компонентов (RTL), e2e на Playwright в репозитории.

**Bonus:** ничего из раздела.

**Известные ограничения:**
- после паузы прогресс загрузки откатывается к последней завершённой части (до 4 × 16 МБ): S3 не сохраняет недогруженную часть;
- уход со страницы проекта внутри приложения отменяет активные загрузки;
- правка комментария меняет только текст, рисунок не меняется. Черновик сохраняет текст, но не рисунок;
- если у участника открыт SSE и его удаляют из workspace, события продолжают приходить до переподключения. Права проверяются при подключении к SSE, а все данные и действия проверяются на каждом запросе;
- J/K/L: браузеры не проигрывают MP4 назад, поэтому J — назад на 1 секунду, K — пауза, L — play, повторное L — 2×;
- проверено в Chromium. Сенсорный ввод для рисования не проверялся.

**Отклонения от ТЗ:**
- **MinIO больше не публикует официальные образы.** Используется сборка Chainguard из исходников (`cgr.dev/chainguard/minio`), закреплённая по digest.
- **MinIO не поддерживает bucket CORS и lifecycle-правило `AbortIncompleteMultipartUpload`** (проверено на живом сервере: `NotImplemented` и `MalformedXML`). Вместо них используются серверные настройки `MINIO_API_CORS_ALLOW_ORIGIN` и `MINIO_API_STALE_UPLOADS_EXPIRY`. Дополнительно задача worker раз в час прерывает брошенные загрузки старше суток. Поэтому `minio-init` только создаёт бакет.
- Turbopack кладёт в `.next/static/media` копию `hash.worker.ts` (артефакт от `new URL(…, import.meta.url)`). Браузер её не загружает, воркер собирается отдельным чанком. Это единственный `.ts` в runtime-образе.

## Структура

```
src/app/            маршруты: тонкие страницы и Route Handlers
src/features/<x>/   фичи: schema.ts (zod, общий для клиента и сервера), server.ts / queries.ts (server-only),
                    actions.ts (Server Actions), components/, чистая логика с тестами рядом
src/server/         инфраструктура: env, db + schema, redis, s3, очереди, письма, логи, SSE-хаб
worker/             фоновые задачи (медиа, письма, очистка, напоминания)
scripts/            миграции и seed (контейнер migrate)
drizzle/            SQL-миграции
docker/             скрипт minio-init
```
